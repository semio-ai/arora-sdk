# test-behavior-tree-nodes

A Rust guest of behavior-tree node functions, declared in a
[`module.yaml`](module.yaml) and generated by
[`arora-module-rust`](../../crates/arora-module-authoring/rust/readme.md): the
test that the generated path — bindings from YAML, served as a
`wasm32-wasip2` component — works, and that a module's control node ticks its
children through the engine.

Its control nodes (`seq`, `seq_star`, `fallback`, `parallel`) take their
children as their first parameter, `children`, an array of `TickId`s, and tick
each with `arora_dispatch_indirect`, calling back into the host. The other
functions are leaves: `succeed`, `fail`, `run`, `status_identity`, the string
nodes `set_str`, `unset_str`, `is_str_set`, `wait_str_set` and `regex_match`,
and `store`, `increase`, `cos` and `add`.

The control nodes, the status leaves and the string nodes are also native to
[`arora-behavior-tree`](../../crates/arora-behavior-tree/readme.md) under the
same ids: a tree ticks those natively and never reaches this module's copies.

## Build

[`build.rs`](build.rs) adds the `Status` and `TickId` records to a registry,
resolves `module.yaml` against it, writes the records the module names to
`records/`, and generates `src/arora_generated/`, which git ignores; the
generated code names the Rust `Status` and `TickId` rather than generating
its own. [`src/lib.rs`](src/lib.rs) implements the functions and serves them
with `arora_module::artifact!(arora_generated::export)`.

```bash
cargo build -p test-behavior-tree-nodes --target wasm32-wasip2
```

The integration tests and polly's tests build it as an artifact dependency
and load the component; its header is
`src/arora_generated/header.json`. Built for the host, its calls into the
engine panic.
